## Findings and what was done

1. **The pin finder could short two SoC outputs (most important).** `utilities/probe/bay_gpio_pattern.sh`
   made PG0-PG2 all push-pull outputs, low, and raised one at a time; checklist step 4 put a hook clip on one
   of three adjacent connector pins and checked it only against holes 8 and 9. A clip touching a neighbouring
   PG pin joined two driven outputs (also the WiFi SDIO lines). The probe README told the user to measure
   "each contact" while the pattern runs, and said no register tells port G's voltage (Check Pins reads
   PIO_POW_VAL).
   **Done (420a8a8):** only the pin under test is ever an output, the other two stay inputs, also between
   its high phases; refusals and the WiFi / SDIO interlock unchanged. The probe suite samples the three
   pins at every `sleep` of the script and fails on two outputs at once; two new mutants (all outputs, the
   pin under test left an output) are killed. Step 4 also requires above 10 Ω from the clip to each
   neighbouring connector pin with the goggle off; the README points to step 4 (one clip per boot, attached
   with the goggle off) and names PIO_POW_VAL.
2. **No mutation testing of the C safety code.** `hdmi_boot_test.sh`, `it66121_seq_test.sh` and
   `pcmbridge_test.sh` claimed "test/mutants.sh uses it", but that script mutates only the shell kit. The
   reviewer's 20 C mutants: 14 killed; real survivors: module.c `read_reg` ignoring the sunxi_dump lock,
   `read_reg` accepting two of three reads, the IT66121 Reg04 check comparing only the audio bits, a single
   Reg04 read; equivalent survivors: the Reg04 read-modify-write, the missing newline check. A leaked lock in
   `system_exec_sunxi_dump()` made `hdmi_boot_test.sh` hang with no time limit.
   **Done (f68fc76, 766f035):** `utilities/probe/test/c_mutants.sh` runs 22 C mutants (the reviewer's 20,
   one for the EDID checksum, one for the new Module Bay status) against the tests that cover them: 21
   killed, 1 marked equivalent (the read-modify-write: its value comes from a check that has just required
   the video/HDCP/RCLK bits to be 0). New checks kill the four real survivors and the newline mutant (an
   answer of eight digits and a stray character without a newline). Every C test program runs under a
   time limit (`TEST_TIMEOUT`, default 300 s); the comments name c_mutants.sh.
3. **Host-dependent tests.** `module_bay_test` opened the real `/tmp/.sunxi_dump.lock` (6 checks failed as
   an unprivileged user after a root run had created it). `it66121_seq_test.sh` and `it66021_edid_test.sh`
   took their base with `git show` from the worktree (exit 128 on a copy) and defaulted to 8364a43, not the
   base a85841d.
   **Done (766f035, f68fc76):** the lock path is a variable the test points at its own directory; the two
   tests compare with a85841d (the IT66121/IT66021 files are identical in both), from git or from
   `BASE_SRC=<a tree of a85841d>`, and say SKIP (exit 77) on a copy without either.
4. **Misleading Module Bay status.** With PG_CFG0 unreadable the page said "Paused, pins in use by WiFi".
   **Done (766f035):** "Paused, pin state unknown" (orange), in all five languages, measured by
   check_strings.py, tested in module_bay_test.
5. **Doc errors.** first-flash.md and checklist step 3 lacked "Not read: pin state unknown"; first-flash.md
   8.1 said git shows no change under `mkapp/app/script/` (rc.sh changed); custom-build.md had "within about
   2 s", the old labels "Record What I Hear" / "Analog RX Audio" and "battery ADC" (it is the analog-RSSI
   ADC); audio.md described the 2 s watcher that gives up; module-bay.md showed old page strings.
   **Done (9563dad, 420a8a8).**
6. **Notes for the docs.** (a) The official sys_config: `vcc-pg` on `axp2101_bldo1` with the `vcc18-*`
   loads (line 1636), `;bldo1_vol = 1001800` commented out (line 47), `wlan_io_regulator = "vcc33-wifi"`
   (line 1190) with no regulator of that name: the 1.8 V bank is a guess from names, Check Pins settles it.
   (b) `HDZG_OS.bin` also holds a full `app.fex` (app 9.5.0, stock rc.sh), so the emergency update
   presumably also replaces a broken app partition (read from the image, not run). (c) See the suspicion
   below. **Done (420a8a8: module-bay-mod-safety.md; 9563dad: first-flash.md).**
7. This page and [status.md](status.md).
